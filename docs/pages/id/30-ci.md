# CI & pre-commit

Checker yang memblokir seluruh repo di hari pertama akan dihapus dari CI di hari yang sama. Yang bekerja: **gate hanya file yang berubah**.

## GitHub Actions

`.github/workflows/standards.yml` di repo kamu:

```yaml
name: standards

on:
  pull_request:
  push:
    branches: [main]

jobs:
  schema:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0        # butuh history untuk git diff

      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Report existing debt
        run: |
          python scripts/check_schema.py . --json > report.json || true
          python - <<'PY'
          import json, pathlib
          d = json.loads(pathlib.Path("report.json").read_text() or "{}")
          print(f"{d.get('files',0)} file, {d.get('errors',0)} error, {d.get('warnings',0)} warning")
          PY

      - name: Gate changed files
        if: github.event_name == 'pull_request'
        run: |
          git fetch --no-tags --depth=1 origin "${{ github.base_ref }}"
          CHANGED=$(git diff --name-only --diff-filter=d "origin/${{ github.base_ref }}"...HEAD \
            | grep -E '\.(sql|php|prisma)$' || true)
          if [ -z "$CHANGED" ]; then echo "no schema files changed"; exit 0; fi
          echo "checking: $CHANGED"
          python scripts/check_schema.py $CHANGED
```

Kuncinya dua baris: `--diff-filter=d` (file yang dihapus tidak diperiksa) dan `$CHANGED` (hanya yang berubah yang digate).

## Pre-commit

`.pre-commit-config.yaml`:

```yaml
repos:
  - repo: local
    hooks:
      - id: ironclad
        name: ironclad schema conventions
        entry: python scripts/check_schema.py
        language: system
        files: '\.(sql|php|prisma)$'
        pass_filenames: true
```

Hook lokal lebih cepat memberi umpan balik, tapi **jangan** menjadikannya satu-satunya gate — hook bisa dilewati dengan `--no-verify`. CI tetap wajib.

## GitLab CI

```yaml
standards:
  image: python:3.11
  script:
    - git fetch origin $CI_MERGE_REQUEST_TARGET_BRANCH_NAME || true
    - |
      CHANGED=$(git diff --name-only --diff-filter=d \
        origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME...HEAD | grep -E '\.(sql|php|prisma)$' || true)
      [ -z "$CHANGED" ] && exit 0
      python scripts/check_schema.py $CHANGED
  rules:
    - if: $CI_MERGE_REQUEST_IID
```

## Menyetel tingkat gate

CI membaca `.agent/standards.yml`, jadi mengubah tingkat penegakan **tidak menyentuh workflow**. Satu baris PR di repo:

```yaml
rules:
  DB-03: error      # dari warn
```

Kalau sebuah PR mengubah severity dan sekaligus menambah pelanggaran baru, reviewer melihat keduanya di diff — dan itulah tujuannya.

## Saat gate terus merah

Urutan penyelesaian yang benar:

1. **Perbaiki schema-nya.** Kalau kolom memang status, jadikan kode integer + lookup. Ini yang seharusnya terjadi pada 90% kasus.
2. **Turunkan satu aturan ke `warn`**, dengan alasan di PR. Sah, tercatat, dan bisa dikembalikan nanti.
3. **Matikan aturan** hanya kalau aturannya memang salah untuk repo itu — dan ubah juga `.agent/standards.md` supaya dokumen dan mesin tidak bertentangan.

Yang **tidak** boleh: menambahkan `|| true` di workflow. Itu bukan pengecualian, itu menghapus alatnya sambil pura-pura masih memakainya.

## Melaporkan ke PR

Kalau ingin anotasi baris di GitHub, pakai format `file:line:`, yang sudah dikenali banyak alat:

```
bad.sql:4: [DB-01] ERROR SQL/prisma enum column
```

Atau hasilkan SARIF untuk integrasi penuh:

```bash
python scripts/check_schema.py . --json | jq '{...}' > results.sarif
```

Belum ada konverter SARIF bawaan — kalau kamu butuh, itu pekerjaan setengah hari dan masuk akal untuk organisasi besar.
